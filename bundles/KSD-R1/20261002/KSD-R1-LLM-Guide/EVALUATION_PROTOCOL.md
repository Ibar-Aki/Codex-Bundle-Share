# KSD-R1 改善前後の同等性と性能の評価仕様

作成日: 2026-10-02 00:10 JST
作成者: Codex (GPT-6)
文書版: 1.0

本書は[統合実装指示書](LLM_IMPLEMENTATION_GUIDE.md)の受入仕様です。Aは最新の完全な現行版、BはAから作る候補版です。旧復元版、Pythonの代用計算、以前の配布物検査をA/Bの実機受入証拠にしません。

## 1. 比較の原則と状態

同じエンジンのA/Bを比較します。ExcelのAとiPhoneのBを比較して同等性としません。Excel、Designer変換後、iPhone保存後、最終出力をそれぞれ確認します。

| 状態 | 意味 |
|---|---|
| PASS | 条件・件数・証拠が揃い、基準を満たした |
| FAIL | 説明不能な出力差、設定差、採用基準の違反がある |
| NOT_RUN | 実施していない、資料・環境・値の取得方法が不足している |
| INCONCLUSIVE | 実施したが、ばらつき・欠測等で結論が出せない |
| NOT_APPLICABLE | 現行運用に機能が存在しない。根拠を記録する |

NOT_RUNやINCONCLUSIVEをPASSへ丸めません。内部値が取れないことはNOT_APPLICABLEではありません。機能を候補から削除したことも該当しません。必須項目に未確認があれば本番採用を完了扱いにしません。

## 2. 比較対象を固定する

`source_manifest.json`にA/BのExcel SHA、帳票定義ID・revision・export SHA、マスターと生成表の型を含むハッシュ、変更器版、ケース集合のハッシュを記録します。端末モデル・iOS・i-Reporter・Designerの版、クラスター設定・丸め・ネットワーク・出力設定も固定します。

版変更で帳票の識別番号や生成時刻が変わる場合は、許容するメタデータ項目名だけを列挙します。数値、入力、クラスターINDEX、CSV列、保存値等を「メタデータ」として除外しません。A/B定義IDとrevisionは別でもよいですが、比較する設定内容が追跡可能であることが必要です。

Aの期待値はBの実装前に取得し、A/B双方で同じ実入力値・型・順序・初期状態を再現します。派生セルを直接上書きせず、上流の実入力クラスターから到達させます。ケースを後から変更した場合は新しいケース版でA/B両方を再測します。

## 3. 機能試験の母集団とケース

### 3.1 母集団を作る

完全な本番マスター全行と到達可能な選択肢を一覧化します。重複、到達不能、未使用行も一覧に残し、除外した理由を記録します。復元版497データ行、旧1693行の終端、旧21セルだけに試験母集団を固定しません。

以下の3層を分けます。

1. 数式単体：本番全マスター行・各返却列を対象に、同じ型のキーと値でA/Bを比較。
2. 入力経路：本番で到達可能な全仕様×左右を、実入力から再現して比較。
3. 操作経路：代表ケースと境界ケースで、修正・消去・連続切替・保存・コピー等を比較。

仕様文字列を都合よく分割して架空の入力を作りません。単体試験用の直接値投入と、利用者の操作を通した試験を同じ実績として数えません。

### 3.2 必須のケース群

| ID | 内容 | 確認すること |
|---|---|---|
| F01 | 本番の全マスター行、返却元の全対象列 | 検索結果・型・最初の一致行が同じ |
| F02 | 到達可能な全仕様×左右、実在する各分岐 | キー・左右列選択・符号・調整値・全依存先が同じ |
| F03 | 変更したキー要素を1項目ずつ入力→修正→消去→再入力 | 最新キー・結果へ更新。派生キーは上流入力から操作 |
| F04 | 未登録キー、同じ/異なる値を持つ重複キー、末尾空白等 | 元の完全一致・行順・未登録時の挙動を維持 |
| F05 | 真の空欄、式の空文字、数値0、文字列"0"、数値文字列、エラー | 型変換・IFERROR・未入力判定の違いがない |
| F06 | 0、正負、許容小数、全入力可能範囲、最大・最小 | 演算順・精度・丸めが同じ |
| F07 | 各判定の境界そのもの、直前・直後 | 合否が一致。刻みは現行で許容する最小入力単位 |
| F08 | 測定行先頭・末尾・切替境界、共通調整値変更 | 旧例の1/12/13/24行を含め現行構造で網羅。広い波及先が更新 |
| F09 | 主キーと別キーを別々に変化させる | 両キーを誤統合しない。旧値や誤った行位置を再利用しない |
| F10 | 下書き保存→再開、帳票コピー、連続した仕様変更 | 保存・コピー元の古い補助値が残らない |
| F11 | オフライン入力→保存→オンライン同期 | 手順・結果・外部出力が同じ |
| F12 | 画面・リスト・印刷/PDF・CSV・外部連携 | 既存見た目・INDEX・列順・値を維持。補助値が追加露出しない |

F04/F05の状態が本番入力で禁止される場合は入力制約の一致を確認し、式の単体試験は配布しない専用コピーで行います。本番の制約や正本データを緩めません。入力で到達不能でも、元マスターに存在する型・重複は表生成の試験で扱います。

全部の変数の総当たりは不要です。全仕様×左右に加え、全分岐、全変更キー要素、変更経路、型、境界を網羅するケースへ絞ります。未検証の組合せと縮約理由を残します。境界は新しい計算ルールで作らず、Aの計算と判定から取得します。

## 4. 何をどう比較するか

変更セルだけでなく、現在の参照関係から辿った全依存先、設定によるネットワーク・コピー・外部連携先を比較します。旧21セルは最低限の手掛かりです。別キー検索の変更、版変更、補助追加があれば対象は増えます。取得可能な全計算クラスターも同一入力状態で比較します。

| 対象 | 比較するデータ |
|---|---|
| Excel | Formula、Value2等の未丸め値、値の型、エラー種別、表示文字列、設定差分 |
| Designer | 変換後の実計算式、既存INDEX、データ型・桁数・丸め・表示/非表示、入力/コピー/ネットワーク/出力設定 |
| iPhone | 計算が完了した表示、取得可能な未丸めの保存値と型、合否、更新後の状態、出力値 |
| 帳票・CSV等 | 値と型、列・順序、表示精度、背景・補助値の露出、連携の契約 |

数値は同じエンジンで取得した未丸め値を正確に比較します。許容誤差を勝手に設定しません。保存形式の桁数が不足する場合は取得精度を調査し、確保できなければ未丸め値の同等性はNOT_RUNとして残します。表示一致だけで内部値一致を断言しません。

`blank`、`string`（空文字を含む）、`number`、`boolean`、`error`を区別します。数値文字列の文字列のままの値をJSON数値へ変換しません。表示の〇/×、空文字、スペースや改行も保持します。

ExcelとiPhoneでは型表現・計算エンジンが異なるため、エンジンをまたいで生データを同一形式に無理に変換しません。同じエンジン内でA/Bを比較し、別エンジンにしかない情報は独立の確認項目にします。

## 5. 位置ずれ対応と適用器の試験

実装時に対応付けや変更器を作る場合、以下を実施します。文書上に手順を書いただけでPASSにしません。

| ID | 試験 | 期待する結果 |
|---|---|---|
| S01 | セル・シートの位置ずれ、シート名変更、マスター列挿入を含むコピー | 役割を再対応し、参照先・分岐・列の意味・型が一致した対象だけ変更 |
| S02 | 同じ式の別セル、似たシート、候補が複数あるコピー | AMBIGUOUSとして書込み停止 |
| S03 | キー順、定数、分岐、型、TRUE/FALSEが異なるコピー | 位置ずれとして吸収せず停止 |
| S04 | 誤ったSHA、変更前式が1つ違う、旧新混在のコピー | 書込み前に全体停止。部分適用版を納品しない |
| S05 | 記録済みの適用済み候補を再処理 | 内容・SHA照合後、変更0 |
| S06 | マスター追加・型変更・順序変更、古い生成表 | 全件再生成。型・行対応・重複先頭を照合し、古い表は拒否 |
| S07 | 保存・再オープンとOOXML/設定の全体差分 | 許可外の式・値・書式・図・印刷・コメント・設定変更0 |

単なるZIP内のタイムスタンプ差は内容差分と区別します。正当なキャッシュ更新等の差も項目と理由を記録し、無制限の除外にはしません。

## 6. iPhoneで測る性能

### 6.1 シナリオと測定対象

| シナリオ | 開始t0→終了t1 | 主に見る負荷 |
|---|---|---|
| P01 起動 | 帳票を開く操作→初期の全関連計算と入力可能状態が安定 | 取り込みデータ量、全初期計算、表示 |
| P02 仕様変更 | 入力の確定→全依存値・合否・操作可否が最新値で安定 | キー検索、広い再計算 |
| P03 通常測定値変更 | 実入力の確定→影響する値と合否が安定 | 日常操作の再計算 |
| P04 共通調整値変更 | 入力の確定→全測定行の依存結果が安定 | 約100箇所へ波及する経路 |
| P05 ページ切替 | 現行の切替操作→対象ページが操作可能 | 表示、補助追加の副作用 |
| P06 下書き保存・再開 | それぞれ操作→完了 | 保存・復帰・古い値の再利用 |
| P07 サーバー保存・同期 | 操作→同期完了 | 通信と送信量。計算応答とは別集計 |

主指標は事前のA測定から最も重い利用頻度の高い操作を1つ選びます。仕様変更が主な待ち時間ならP02を主指標にします。速くなった操作を結果を見てから主指標に選び直しません。

起動を一括にせず、実施可能な範囲でアプリ再起動後の起動と、同セッションの再表示を区別します。帳票定義の端末への初回配布時間は別指標です。キャッシュを制御できない測定を「完全なcold」と呼びません。ユーザーデータや下書きの削除を測定準備として行いません。

### 6.2 同条件の対比較

同じ端末・iOS・アプリ版で、A/Bの同一ケースを近い時間に測ります。版更新は別実験です。端末機種、低電力モード、電池、温度、空き容量、通信状態、バックグラウンド作業を記録し、条件を揃えます。

オフラインの計算応答と、安定した同じWi-Fiでの通信を分けます。Aだけオンライン、Bだけオフラインという比較はしません。計算と通信が混ざるシナリオでは両者を分離できる範囲と限界を記録します。

初期状態へ戻し、同じ入力順・同じ変更値を使います。同じ値を再設定して再計算が発火しない操作を試行に数えません。各試行は計算・保存が落ち着いてから始め、初回準備や欠測を勝手に正常時間へ混ぜません。

標準の初回評価では、通常入力・仕様変更を**各30対以上、3セッション以上**に分けて測ります。起動は各条件**10対以上**を初回目安とします。AB、BAの順番を均等にし、例えばABBAブロックで順序・温度・慣れの偏りを抑えます。順番と対番号を生データへ残します。測定誤差が大きければ追加試行で確認します。

ケース、試行数、除外規則、主指標、採用基準を測定前に確定します。除外は通知割込み・操作ミス・計測不能等の事前規則に限り、除外した試行と理由も残します。遅い試行を都合よく消しません。

### 6.3 時間の取り方

既存環境で信頼できる計測ログが取れるなら使用します。取れなければ画面録画等でt0/t1のフレームを記録します。入力途中のタップからではなく、入力確定から計算結果・合否・操作可否が安定するまでを同じ基準で測ります。一部の表示だけ先に変わった時点で終了しません。

録画の実フレームレート、開始/終了フレーム、時間分解能を残します。60fpsなら1フレーム約16.7msですが、開始・終了の判断誤差もあります。1～2フレームの差を安定した改善と扱いません。基準の0.10秒より測定の不確かさが大きければ測定方法を改善し、結論を保留します。

## 7. 集計と採用基準

`performance_measurements.csv`は1試行1行で、同じ`scenario_id,case_id,session_id,pair_id`のA/Bを対にします。未完了・結果不一致の試行を、速かった試行として集計しません。

まずA/Bそれぞれの中央値、p95、最小/最大、件数、欠測・除外を示します。p95は使用した算出方法を残します。10対や30対のp95は不安定な参考値なので、ばらつきが大きい場合は追加測定します。

各対の短縮時間は`A秒-B秒`、短縮率は`(A秒-B秒)/A秒`です。A秒が0または測定分解能以下の対は率で評価せず、方法を見直します。「中央値の比」と「対ごとの短縮率の中央値」を混同せず、両者を区別して残します。

平均だけで決めず、対ごとの差の中央値、セッション別の結果、遅い試行の分布を確認します。対比較のブートストラップを使う場合はセッションを考慮し、再標本化方法・乱数seed・回数を記録します。少数セッションから求めた区間を一般的な安定性の保証としません。差が計測誤差やセッション間変動の範囲ならINCONCLUSIVEです。

以下は**事前合意のための推奨初期基準**です。業務上の基準があれば測定前に置き換えます。結果を見てから緩めません。

- 機能・設定・出力の必須項目はすべてPASS。説明不能な差分0。
- 主指標の対ごとの短縮率中央値が20%以上、かつ短縮時間中央値が0.10秒以上。
- 各セッションの主指標の短縮時間中央値が正。結論が順序や1セッションだけに依存しない。
- 他の重要シナリオで、中央値が5%超かつ0.10秒超悪化しない。
- p95が10%超かつ0.10秒超悪化する兆候があれば追加測定。再現すれば不採用。初回の少数測定だけで非劣化PASSにしない。
- 応答の不安定化、古い結果、操作追加、連携への補助値露出は速度改善があっても不採用。

20%はこのExcelで実現すると保証した値ではありません。実装コストに見合うかを判断する目標です。数式回数の比、Excelの再計算時間、ファイルサイズだけからiPhoneでの短縮率を算出しません。

## 8. 必須gateと納品判定

| gate | 必須の証拠 |
|---|---|
| G01_SOURCE | A/B・定義・マスター・環境・ケースの識別、SHA |
| G02_BINDING | 全必要役割の一意な対応、現在の依存先、位置ずれ試験 |
| G03_PATCH | 許可差分、旧式照合、保存後差分、安全な再実行、生成表の整合性 |
| G04_EXCEL | 現行エンジンのA/B未丸め値・型・判定・境界の一致 |
| G05_DESIGNER | 再取り込み後の実式と既存クラスター・型・設定保持 |
| G06_IPHONE | 実入力・変更・消去・再開・コピー・オフラインの一致 |
| G07_OUTPUT | 表示・最終帳票・CSV・実在する外部連携の一致 |
| G08_PERFORMANCE | 同端末の対比較、生データ、事前基準による採否 |
| G09_ROLLBACK | 検証環境で旧版復帰と代表ケースの再確認 |

関連操作が現行に存在しない場合は、該当試験を理由付きNOT_APPLICABLEにできます。必要なデータが入手できないgateはNOT_RUNです。適用器を作らない場合でもG03の手作業差分・保存確認は必要です。

納品は「採用」「不採用」「評価未完了」を明記します。評価未完了の候補を、本番へ取り込める完成品として配布しません。候補で作成した帳票の扱いも含め、切戻し版と証拠を一緒に保持します。
