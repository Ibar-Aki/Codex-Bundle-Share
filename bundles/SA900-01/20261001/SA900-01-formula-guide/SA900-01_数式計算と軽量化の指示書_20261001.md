## 1. 目的と適用範囲

対象は境界条件修正版v4（2026-09-24）です。階名表示の式を起点に、DB取得から出力②までの考え方、旧式との処理量の差、保守とi-Reporter確認の要点を整理します。この文書は計算の説明・今後の確認指示であり、新しいExcel改修の完了報告ではありません。

比較対象のファイル名、SHA-256、集計値は[formula_comparison.json](formula_comparison.json)に記録しています。数式数の削減率は実機の速度短縮率ではありません。例示値はv4に保存済みの基準入力結果で、今回新たに再計算した結果ではありません。

## 2. 階名取得の流れ

```text
帳票基本入力!C5（階床構成）
  → 計算用シート!Y4（DB登録件数）
  → 計算用シート!Z45:Z68（24個の階名取得）
  → 入力①のB/K/T列（表示）
  → 計算用シートのB45:B68（計算用の階名）
  → 階高・部品・累積高さ・取付位置
```

計算用シートのZ列はDBと入力キーから決まります。後段のB列がZ列へ依存を戻さないため、この流れ自体は循環参照ではありません。

### 2.1 キーが一意か確認する

Y4:

```excel
=IF(帳票基本入力!C5="",0,COUNTIF(塔内機器_入力①_DB!$C$2:$C$937,帳票基本入力!C5))
```

0は空欄または未登録、1は一意、2以上は重複を表します。検索表は2～937行の936行です。VLOOKUPの完全一致だけでは重複キーを検出できないため、検索前に登録件数を確認します。

### 2.2 階名を取得する

Z45:

```excel
=IF($Y$4<>1,0,IFERROR(VLOOKUP(帳票基本入力!C5,塔内機器_入力①_DB!$C$2:$AA$937,2,FALSE),0))
```

一意なキーなら、完全一致で表の2列目（D列）を取得します。Z46は3列目（E列）、Z68は25列目（AA列）を取得します。24個を一度の検索で取得する仕組みではなく、24セルがそれぞれVLOOKUPを1個持ちます。

基準入力のキーは`1-7`で、DBの201行にあります。D201～J201は文字列の`1`～`7`、その後の階欄は空欄です。Z45～Z51に階名が入り、Z52以降は0として扱われます。

### 2.3 帳票へ表示する

入力①のB36:

```excel
=IF(塔内機器_計算用シート!Z45=0,"",CONCATENATE(塔内機器_計算用シート!Z45))
```

0なら空欄、それ以外なら文字列として表示します。これは階名の表示式で、寸法を算出する式ではありません。基準入力で表示される`1`は階名であり、1mmを意味しません。

表示先は24欄です。Z45～Z52はB36/B40/B44/B48/B52/B56/B60/B64、Z53～Z60は同じ行のK列、Z61～Z68は同じ行のT列へ対応します。

0を表示抑止の印として使うため、数値0や文字列`0`を正式な階名として使う運用は別途整理が必要です。未登録・重複・検索エラーを表示上は空欄にするため、空欄だけで正常と判断せず、入力状態の警告も確認してください。

## 3. 階高と部品・取付位置への接続

計算用B45は入力①!B36を参照します。C45は、隣接する階の有無と階高の入力検査を確認して入力①!E38を取り込みます。階名はDBから、階高は寸法入力から取得する別の情報です。

| 基準入力の項目 | 保存値 | 用途 |
|---|---:|---|
| B45 | 1（文字列） | 階名 |
| C45 | 3,745mm | 次の階までの階高 |
| E45 | 1 | 部品選定用の階番号 |
| G45 | 3,745mm | 部品選定に使う区間の高さ |
| Y6 | 104 | 機種グループ |
| I45 | 10,403,745 | 機種グループ×100000＋区間高さ |
| K45 | 420【1】+800【1】 | 部品寸法と員数 |

G列はSUMIFで同じ階番号に属するC列の高さを集計します。通常の階では該当階の階高です。`N`を含む構成では、E列で`N`のカウントを除く処理と合わせて区間をまとめます。`N`の業務上の意味は元の帳票運用に従い、文字列を勝手に置換しないでください。

K列の部品選定では、入力成立、最上階、機種グループ、DB範囲、推定データの確認状態を検査してからDBを参照します。最上階の基準入力結果は`無し`です。階名がない行は部品を表示しません。

取付位置については階高を下から累積した表を使います。出力②!E35は取付高さD32から該当階名を近似検索し、L35は取付高さからその階のFL高さを引きます。基準入力の保存結果は「5階FLから2,326.5mm」です。部品選定の区間高さと、FL判定の累積高さを混同しないでください。

## 4. 元のVLOOKUP式との比較

旧B36の構造:

```excel
=IFERROR(IF(VLOOKUP(入力表!J32,塔内機器_入力①_DB!C2:AA937,2,FALSE)<>"",VLOOKUP(入力表!J32,塔内機器_入力①_DB!C2:AA937,2,FALSE),""),"")
```

条件判定と値の取得に同じ検索を2回記述していました。v4では検索結果をZ列へ置き、表示式はその結果を参照します。CONCATENATEを使ったことが軽量化の中心ではありません。

| 指標 | 復元マスター | 推定補完版v1 | v4 |
|---|---:|---:|---:|
| 数式セル数 | 1,589 | 2,852 | 875 |
| VLOOKUP記述総数 | 149 | 204 | 179 |
| 階名取得部分のVLOOKUP記述数 | 46 | 48 | 24 |
| 出力②_DBの数式セル数 | 1,014 | 2,260 | 20 |
| 計算用シートの数式セル数 | 303 | 303 | 589 |

復元マスターのB60は固定値7で、階名表示の数式が23欄でした。v1は24欄すべてが数式なので、48→24の比較はv1を基準にします。

- 階名取得のVLOOKUP記述数: v1比50.0%削減。ただしY4のCOUNTIFを1個追加しています。
- 全体の数式セル数: v1比約69.3%削減。
- 全体のVLOOKUP記述総数: v1比約12.3%削減。
- 復元マスター比ではVLOOKUP総数は149→179と増加。追加検査を含むため、元ファイルよりすべての検索が減ったわけではありません。

固定DBキーなどを値にしたことで再計算対象が減りました。一方、入力やDBの安全確認のため計算用シートの式は増えています。DBの固定キーに影響する機種・区間設定を変更する際には、値の再生成と検索範囲の確認が必要です。

## 5. 性能について言える範囲

集計しているのは数式内の記述数です。実行回数はIFの分岐、変更した入力、再計算対象、実行エンジンに依存します。COUNTIFと参照・表示の処理もあるため、48→24を「処理時間50%短縮」「2倍速」と読み替えないでください。

確実な改善は、重複検索の削減、固定DBの再計算対象削減、取得結果と検査結果の追跡のしやすさです。ExcelでもiPhoneでも処理時間の測定は行っていません。

速度を確認する場合は、同じDBと同じ正常入力を使い、入力変更から表示更新までを測定します。7階・24階、階床構成変更・寸法変更を分け、同じ端末・アプリ版で複数回の中央値を比較してください。初回読込と入力後更新を別に記録し、正しさの確認を先に行ってください。

## 6. i-Reporterの互換性と今後の確認指示

2026-10-01に公式資料を再確認しました。CONCATENATE自体は対応関数です。ただし1引数のCONCATENATEのDesigner取り込み・実機動作は未確認です。対応不可と断定したり、関数名だけで帳票全体の動作を保証したりしないでください。

本当に必要な対応は次の順序です。いずれも本配布物では実装・実機試験をしていません。

1. 使用するDesigner・iOSアプリの版と帳票定義を記録し、計算セル・参照先・数値入力のクラスター設定を確認する。欠落したExcelOutputSettingの復元は別作業です。
2. 1引数CONCATENATEを使う24セルについて、文字列である必要と後続の参照を確認する。単なる数値表示なら下記の直接参照式を候補にする。数値と文字列の扱いが変わるため、無条件の一括置換はしない。
3. 変更候補では、通常階、空欄、`N`、地下階、未登録・重複キー、0階の扱いを確認し、旧結果と比較する。
4. Designer取り込みで#REFがないこと、iPhoneで入力変更が後続の部品・取付位置へ反映されることを確認する。検索表の取り込み例外だけで、動的な計算結果の追従まで保証しない。
5. 上記の正しさが確認できた後、必要なら同条件の速度比較を行う。

直接参照への変更候補（未実装）:

```excel
=IF(塔内機器_計算用シート!Z45=0,"",塔内機器_計算用シート!Z45)
```

新しい検索関数への置換やクラスター構成の大幅変更は、これらの確認前に追加しないでください。今回の検証スクリプトは数式とファイルの同一性を検査するもので、i-Reporter互換性やメーカー施工規定の妥当性を判定するものではありません。
